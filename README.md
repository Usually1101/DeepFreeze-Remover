# Deep Freeze Remover

> 忘记密码也能把「冰点还原」(Faronics Deep Freeze) 从 Windows 里彻底摘掉。

## 这是什么

一个面向 **Windows 10 / 11 (x64)** 的绿色工具箱（交互菜单 + 命令行两种用法），
用来在**没有密码**的情况下，把冰点还原从系统里连根清除：

服务 / 驱动登记 → 开机过滤器（`UpperFilters`）→ `Faronics` 注册表 → 安装目录 →
驱动文件 → 卷根目录的 `persi0.sys`。

它**不破解、不读取、不重置密码**。做法是换一个"冰点驱动没加载"的环境
（PE / Windows RE / 另一套系统），在那里按正确顺序把组件摘掉。
对这个需求来说，**"不需要密码"比"拿到密码"更有用**。

## 为什么会有这个项目

三个现实问题：

1. **官方没有后门密码。** Faronics 明确表示不会提供、也无法找回密码。
   忘记密码的机器，官方路径基本只剩"重装系统"或联系支持。
2. **冻结状态下删不掉。** 冰点是磁盘过滤驱动，"重启还原"靠的就是它拦截写入。
   在运行中的系统里删文件、改注册表，重启后原样回来——这是它的设计目的，不是操作失误。
3. **网上教程容易把系统搞蓝屏。** 常见做法是"进 PE 删驱动文件"，但**顺序反了**：
   文件删了、`Services\DFFilter` 和 `UpperFilters` 登记还在，下次开机去加载一个不存在的驱动，
   直接 `0x7B INACCESSIBLE_BOOT_DEVICE`。

这个项目把那套经验固化成脚本：**顺序正确、只动冰点、可回滚、无键盘也能用**。

## 它能做什么

| 能力 | 说明 |
|---|---|
| **扫描** | 只读检测服务/驱动、开机过滤器、注册表、安装目录、数据文件，并判断系统是否处于冻结状态 |
| **在线卸载** | 仅适用于"已解冻"系统；检测到驱动仍在运行会主动拒绝（避免做无用功） |
| **PE 离线卸载** | 主路径。双引擎：纯 CMD（无 PowerShell 的 PE 也能跑）+ PowerShell（带演练、日志、校验） |
| **PE 模式** | 在 PE/RE 里直接运行主工具，自动切换菜单：检测 → 强制卸载 → 复查 → 重启回 Windows |
| **无键盘流程** | 触摸设备双击 `一键卸载-触摸.cmd`，全自动清理 + 自动重启，全程零输入 |
| **UEFI 一次性启动** | 不按热键、不改 BIOS：只把"下一次启动"指向 U 盘（失败自动回退，进过 PE 自动恢复） |
| **环境自检** | 管理员、64 位 PowerShell、目录可写性、BitLocker、`hiberfil.sys`、WinRE、U 盘 |
| **卸载后复查** | 逐项核对服务、过滤器、目录、注册表、数据文件 |
| **配置清单导出** | 只导结构信息（组件、路径、版本、冻结卷推断），**不含密码**，供卸载重装时对照 |
| **备份与回滚** | 注册表备份 + 完整性校验 + 位置自动回退；改 BCD 前自动导出备份 |

## 它不做什么（能力边界）

明确写清楚，避免误解：

- ❌ **不读取、不破解、不重置冰点密码** —— 本项目通过"摘除组件"实现免密码卸载，不涉及凭据。
- ❌ **不修改 BIOS/UEFI 里保存的启动顺序** —— 只做"一次性启动"，重启后自动恢复
  （Windows 本身也没有受支持的接口能改固件设置）。
- ❌ **不处理其它还原软件** —— Rollback Rx / Reboot Restore Rx / Shadow Defender 只**识别并提示**，
  不会去动它们（处理方式不同，误操作风险高）。
- ❌ **不碰内核** —— 没有驱动、没有内存补丁、不需要关驱动签名。
  内核级方案的原理与代价见 [docs/DeepThaw-技术评估.md](docs/DeepThaw-技术评估.md)。
- ❌ **不做密码之外的"绕过"** —— 不碰 BitLocker、不碰安全启动、不碰域策略。

## 设计原则

1. **宁可多一次重启，也不碰内核。** 内核补丁能省一次重启，但要承担蓝屏、杀软拦截、版本绑定。
2. **顺序即安全。** 永远"先摘注册表登记，再删文件"。反过来就是 `0x7B`。
3. **只动冰点。** 过滤器列表按条目精确摘除，`partmgr`、`volsnap` 等原样保留且顺序不变；
   Microsoft 的 DFS 文件（`dfsc.sys`、`dfshim.dll`）永不触碰。
4. **每一步都能回滚。** 改注册表前导出备份；改 BCD 前导出 `.bcd`；备份失败会明确报错并询问。
5. **无键盘可用。** 触摸设备、无实体键盘的机器也能走完全流程。

## 三种典型用法

```
① 有密码           → 用官方卸载（本项目不出场）
② 忘记密码 + 冻结  → [2] 生成离线包 → 进 PE → 双击 一键卸载-触摸.cmd
③ 没有实体键盘     → [10] 设置一次性启动 → 重启进 PE → 双击触摸版 → 自动回 Windows
```

## 兼容性

| 项 | 支持情况 |
|---|---|
| Windows 10 / 11 x64 | ✅ 主要目标 |
| Windows 7 / 8.1 | ⚠️ 未验证（脚本用了 PS 5.1 特性，理论上可行） |
| 32 位系统 | ⚠️ 未验证 |
| UEFI / Legacy BIOS | UEFI 支持一次性启动；Legacy 只能用开机热键 |
| BitLocker | 需先在 PE 中解锁，否则读不到分区 |
| 无 PowerShell 的 PE | ✅ 走 `DF-Offline-Clean.cmd` |
| 无实体键盘（希沃等） | ✅ 触摸版 + 一次性启动 |
| 魔改版 / 国产套壳 | ⚠️ 组件被改名时靠 `ImagePath`/显示名兜底匹配，未必命中 |


## 验证

自检套件 **132 项断言**，全部通过：

```powershell
powershell -ExecutionPolicy Bypass -File .\tests\Test-OfflineClean.ps1 -Which All
```

覆盖：服务/驱动登记删除、多字符串过滤器只摘冰点且保持顺序、仅含冰点的值整体删除、
无关过滤器零改动、所有 ControlSet、Faronics 下其它产品不被误删、幂等、
`-DryRun` 只说不做、备份目录不可用时自动换位、**非 PE 环境拒绝执行**、
清理后注册表仍可正常挂载。

另外做过：PE 模式端到端（`subst` 虚拟盘 + `MiniNT` 标记模拟）、
`bootsequence` 设置→回读→清除往返测试、发布包与源文件逐字节校验。

**尚未验证**：真实冻结机器上的实测（开发环境没有安装冰点）；
真实环境的差异主要在"驱动文件被内核占用"（已用重启后删除兜底）与"魔改版改名"（已加兜底匹配）。
