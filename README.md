# Deep Freeze Remover

> 忘记密码也能把「冰点还原」(Faronics Deep Freeze) 从 Windows 里彻底摘掉的小工具。
> 绿色脚本，不装驱动、不改内核、不读密码。

## 它解决什么问题

冰点还原是「重启就还原」的还原类软件。忘记密码时，官方明确表示**没有后门密码**，
而且它在冻结状态下会拦截所有写入——**在运行中的系统里删它，重启后原样回来**。

本工具不去破解密码，而是**换一个"驱动没在运行"的环境**（PE / Windows RE / 另一套系统），
在那里按正确顺序把它的组件摘除：

```
先摘"注册表里的加载点" → 再删文件
```

顺序反了（先删文件、留着服务与 `UpperFilters` 登记）会导致开机
`0x7B INACCESSIBLE_BOOT_DEVICE` 蓝屏。

## 功能

| 功能 | 说明 |
|---|---|
| **扫描** | 只读检测服务/驱动、开机过滤器、注册表、安装目录、数据文件，并判断是否处于冻结状态 |
| **在线卸载** | 仅适用于"已解冻"的系统（驱动未运行） |
| **PE 离线卸载** | 主场景：PE 里一键强制卸载，自动识别系统盘 |
| **PE 模式** | 在 PE 里直接运行主工具，自动切换成 PE 菜单（检测 / 强制卸载 / 复查 / 重启回 Windows） |
| **无键盘流程** | 触摸设备（如希沃）用「一键卸载-触摸.cmd」：双击即全自动，零输入、自动重启回 Windows |
| **环境自检** | 换电脑先跑 `[5]`：管理员、64 位 PowerShell、可写性、BitLocker、`hiberfil.sys`、WinRE 等 |
| **卸载后复查** | 逐项核对服务、过滤器、目录、注册表、数据文件是否清干净 |
| **导出配置清单** | 只导出结构信息（组件、路径、版本、冻结卷推断），**不含密码**，供卸载重装时对照 |
| **思路对比教程** | [docs/卸载思路对比.md](docs/卸载思路对比.md)：9 条路线的前提、耗时、风险、失败原因 |
| **备份与回滚** | 动手前导出注册表；备份失败会明确报错并可选择继续 |

## 快速开始

```text
双击 Start.cmd  →  按提示操作
```

菜单：

```
[1] 扫描本机（只读）
[2] 生成 PE 离线卸载包（忘记密码时用这个）
[3] 在线强制卸载（仅限已解冻）
[4] 卸载后复查
[5] 环境自检（换电脑先跑这个）
[6] 不想做 U 盘？用系统自带恢复环境（WinRE）
[7] 一键重启到恢复环境（没有实体键盘用这个）
[8] 导出配置清单（不含密码，重装时对照）
[9] 卸载思路对比（打开教程）
```

### 三条典型路径

**A. 有密码** → 用官方卸载（最省事，本项目不需要出场）

**B. 忘记密码 + 系统冻结** → `[2]` 生成离线包 → PE 里双击 `一键卸载-触摸.cmd`
（或 `Start.cmd` 进 PE 模式 → `[2]` 强制卸载）

**C. 没有实体键盘**（希沃等触摸设备）→ `[7]` → 重启后点【使用设备】选 U 盘 →
双击 U 盘里 `DF-Auto\一键卸载-触摸.cmd` → 自动清理并自动重启回 Windows

## 安全设计

- **先摘登记、再删文件**：保证不会因为"驱动器在但登记没了 / 登记在但驱动器没了"而蓝屏。
- **只动冰点**：过滤器列表按条目精确摘除（`partmgr`、`volsnap` 等其他过滤器原样保留且顺序不变）。
- **不会误伤 Microsoft 的 DFS**：`dfsc.sys` / `dfshim.dll` 等文件永不触碰。
- **安全阀**：离线清理器在非 PE 环境会**拒绝执行**——避免在正常系统里误双击把自己弄坏。
- **自动重启受保护**：只有在真正开始清理过之后才允许自动重启；被拒绝、取消都不会重启。
- **过滤驱动在跑时拒绝在线卸载**：冻结状态下在线删是白做，工具会直接拦下并提示改走离线。
- **注册表备份 + 完整性校验**：备份完会真的 `reg load` 验证一次，避免"文件是空的/被截断"。

## 支持范围与已知限制

- 目标：Windows 10 / 11 x64（32 位系统未验证）。
- 识别并清理：Deep Freeze Standard / Server / Enterprise 的常见组件
  （`DFServ`、`DFFilter`、`DeepFrz`、`DfDiskLo`、`FarDisk`、`FarSpace`、`Faronics` 注册表、`persi*.sys`）。
- 只**识别**不处理：Reboot Restore Rx / Rollback Rx / Shadow Defender（会提示你另找方案）。
- **未在真实冻结机器上实测**：本项目在仿真环境（伪造的注册表配置单元 + 虚拟盘 + MiniNT 标记）中做过端到端验证，
  见下方"验证"。真实环境差异主要在驱动文件被内核占用（已用"重启后删除"兜底）与魔改版组件改名（已加兜底匹配）。
- BitLocker 加密盘在 PE 下需先解锁，否则读不到。
- 单文件挂载的 `wim`/`vhd` 启动方式未测试。

## 验证

自检套件 `tests/Test-OfflineClean.ps1`（**132 项断言**，全部通过）：

```
powershell -ExecutionPolicy Bypass -File .\tests\Test-OfflineClean.ps1 -Which All
```

覆盖：服务/驱动登记删除、多字符串过滤器只摘冰点且保持顺序、仅含冰点的值整体删除、
无关过滤器零改动、所有 ControlSet、Faronics 下其它产品不被误删、幂等、
`-DryRun` 只说不做、备份目录不可用时自动换位、**非 PE 环境拒绝执行**、
清理后注册表仍可正常挂载。

另外做过 PE 模式端到端测试（`subst` 虚拟盘 + `MiniNT` 标记模拟 PE）：
检测 → 强制卸载 → 自动复查 → 独立复核，全部符合预期，且无 `hive` 泄漏。
