# 发布流程（固定做法）

> 约定：**每次改动都要发布**。本地验证通过后推送 tag，由 GitHub Actions 自动构建并创建 Release。

## 一、每次发布的固定步骤

```
1. 改代码 / 文档
2. 升版本号（见第二节，三处）
3. 更新 CHANGELOG.md（新增一节，写清"新增 / 变更 / 未包含"）
4. 本地跑一遍自检：tests\Test-OfflineClean.ps1 -Which All
5. 本地打包验证：Build-Release.ps1  （含打包前质检）
6. git add -A && git commit && git push origin main
7. git tag -a vX.Y.Z -m "..." && git push origin vX.Y.Z
8. GitHub Actions 自动创建 Release（含 zip 资产）—— 不需要手工点
```

## 二、版本号三处（必须同步）

| 文件 | 位置 |
|---|---|
| `DFRemover.ps1` | 主流程 banner：`冰点还原 (Deep Freeze) 强制卸载工具  vX.Y` |
| `Offline\DF-Offline-Clean.ps1` | 顶部方框 banner |
| `Offline\DF-Offline-Clean.cmd` | `title` 下方的 banner（**GBK 编码**） |
| `Build-Release.ps1` | `$Version = 'X.Y'`（决定 zip 文件名） |

## 三、自动发版怎么实现的

`.github/workflows/release.yml`：

- 触发：`push` 形如 `v*` 的 tag（也可手动 `workflow_dispatch`）
- 在 `windows-latest` 上执行 `Build-Release.ps1`（质检 + 打 zip）
- 用 `softprops/action-gh-release` 创建 Release 并上传 `dist/DeepFreezeRemover-*.zip`
- 认证使用仓库自带的 `secrets.GITHUB_TOKEN`，**不需要 PAT**

## 四、编辑注意事项

1. **`.cmd` 是 GBK + CRLF**，不能用普通 UTF-8 编辑器直接改再存回；改动后要确认：
   ```bat
   rem 编码应为 GBK(936)，行尾 CRLF，无孤立 LF
   ```
   `.gitattributes` 里 `*.cmd -text` 保证入库不改字节。
2. **`.ps1` 要 UTF-8 with BOM**，否则中文会乱码。
3. 三个脚本里的**冰点组件清单**必须一致（`DFServ` / `DFFilter` / `DeepFrz` / `DfDiskLo` /
   `FarDisk` / `FarSpace` / `DFInstall`），自检用例 0 会检查。
4. 不要提交 `dist\`、`DFBackup_*`、`DF配置清单-*.md`（已在 `.gitignore`）。

## 五、失败排查

| 现象 | 处理 |
|---|---|
| Actions 里 `Build package` 失败 | 多半是编码/语法质检没过，本地跑一次 `Build-Release.ps1` 看详细报错 |
| Release 没生成但 zip 有 | 检查 workflow 的 `permissions: contents: write` 是否保留 |
| tag 推了但没触发 | 确认 tag 名以 `v` 开头（如 `v1.3.0`）；`workflow_dispatch` 可手动补跑 |
| 想重发同一版本 | 删除远端 tag 再重推：`git push origin :refs/tags/vX.Y.Z` → `git push origin vX.Y.Z` |
